## 5. Campaign-level patterns, and the one change that would have prevented the most

**Recurrence counts across the audited range:**

| Class | ~Count | Mechanism |
|---|---|---|
| Fabricated / over-asserted hard edge | 17 | free-text `Depends on:` line, no consumption test |
| Missing hard edge (prose-only reference) | 12 | "the §V.6 comma-creation issue" never resolved to a number |
| Same construction, different module path | 24 | `check_collisions.py` matches **paths**; two issues naming `Theory/Thin.v` and `Structure/Thin.v` are invisible |
| Prose-only increment, no checkbox | 20 | `book-chapter.js:149` requires a checkbox but nothing enforces it |
| Trailer not last / ids or deps out of sync | 20 | anchored regex + silent fallback |
| Stale or off-by-one `file:line` | 11 | citations hand-written, never re-verified |

**Root cause and the single highest-leverage fix.** `check_graph.py:51` is `DEP_LINE = re.compile(r"^\s*[-*]?\s*Depends on:")` — it matches **any line anywhere in the body** and then harvests **every** `#N` on that line, truncating only at `REVERSE_CUE` (line 61), whose alternation contains `Related \(NOT blocking\)` but **not** bare `Related:`, nor `ordering constraint`, nor `NOT supply`. That single regex is responsible for at least six defects directly (#650's `Related:` clause glued on with no newline harvesting #649/#651; #683's and #437's hedges that deny the edge they assert; #333's `(the Top clause of Exercise 1 only)`; #466's and #343's buried edges contradicting a `## Dependencies` section reading `None.`) and enables most of the other 29 edge defects by making the dependency surface unaudited free text.

**Concrete change — one commit in `check_graph.py`, three rules, hard-fail:**
1. **Section-scope it.** Only harvest `Depends on:` lines that appear under the `## Dependencies` heading. Any `Depends on:` line elsewhere in the body is an **error** ("dependency declared outside `## Dependencies`"). Kills #466, #343, #683.
2. **One dependency per physical line, nothing after the label.** Reject any `Depends on:` line containing more than one `#N`, or containing a second sentence after the `#N (\`item-id\`)` label — the reason clause must follow an em-dash and must not contain a `#N`. Kills #650, #333, #437.
3. **Require a resolved label.** Reject `Depends on: #219` with no `(\`item-id\`)` (currently `unresolved_deps` only checks the reverse). This forces the author to name what is being consumed, which is exactly the check that would have caught #263→#260, #272→#219, #363→#220, #365→#289, #372→#223, #374→#238.

**Second-highest leverage — one line in `file_chapter.py`.** Line 224 uses `re.search(r"<!-- catalog: (\{.*?\}) -->\s*$", body)`, anchored to end-of-body; when the trailer is not last it falls to the `else` branch at :230 and appends the block **without ever updating `ids`**, silently. Change that `else` to raise. That single line explains the missing trailer ids on #370, #373 and #416, and would have surfaced all seven trailer-not-last bodies the first time anyone appended to them. Pair it with a `check_graph.py` assertion that every body ends with the trailer.

**Third — key `serialize-groups.json` on construction, not path.** The file has 19 entries, all keyed on a `.v` path, and `check_collisions.py`'s own header documents the blind spot. Twenty-four duplicate-deliverable findings are the same shape: two issues declare the same Coq identifier under two proposed paths. Allow a non-path key (as Group H items 1 and 4 do) and have `check_graph.py` warn when two issues' Work sections declare the same **identifier** — `grep` for `` `Identifier` `` in the Work/DoD/Verification sections and cross-index — rather than only the same file.
